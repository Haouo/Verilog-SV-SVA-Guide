# 第一部 · 5. 循序邏輯

[← 組合邏輯](04-combinational-logic.md) · [目錄](../README.md) · [下一章：有限狀態機 →](06-finite-state-machines.md)

## 學習目標

- 以帶時脈的 `always` 區塊推斷正反器（flip-flop）。
- 在循序邏輯中使用非阻塞式指定（non-blocking assignment），並理解原因。
- 在同步重置與非同步重置之間做出選擇。
- 避免阻塞式/非阻塞式指定的經典競態（race）問題。

## 設計者的心智模型

循序邏輯是時間化為狀態的地方。clock edge 取樣輸入值，並寫入新的 register 值；兩個 edge 之間，
register 維持原值。程式碼的寫法應該清楚呈現這個取樣的過程，這也是循序邏輯預設採用非阻塞式指定的原因。

重置同屬這個過程。它界定設計在初始化或復原之後承諾進入哪個狀態。reset 分支不是裝飾，而是明確回答：
「在正常運作開始之前，哪些值必須是安全的？」如果這個答案不清楚，後續的 assertion 與 testbench 也會跟著模糊。

## 推斷正反器

循序邏輯（sequential logic）的狀態會在時脈緣更新。用時脈緣觸發的 `always` 區塊就能推斷出正反器：

```verilog
always @(posedge clk) begin
    q <= d;
end
```

這代表：在 `clk` 的每個上升緣，`q` 取得 `d` 的值，也就是一個 D 型正反器。敏感度列表裡的 `posedge`（或 `negedge`）讓這段邏輯成為循序而非組合。

## 循序邏輯使用非阻塞式指定

在帶時脈的區塊內，請使用非阻塞式指定 `<=`，而非阻塞式指定 `=`。這是 Verilog 中最重要的規則之一。

- **阻塞式（`=`）** 立即按順序執行，如同軟體語句。
- **非阻塞式（`<=`）** 先取樣所有右側值，再在時間步結束時統一更新所有左側目標。

非阻塞式指定正好對應真實正反器的行為：所有正反器在時脈緣同時取樣輸入，再一起更新。以移位暫存器（shift register）為例：

```verilog
// Correct: all three FFs sample, then all update
always @(posedge clk) begin
    q1 <= d;
    q2 <= q1;
    q3 <= q2;
end
```

使用 `<=` 時，`q2` 取得的是*舊*的 `q1`，與硬體行為一致，形成三級移位暫存器。若改用 `=`，`q1` 會先更新，`q2` 讀到的就是*新*的 `q1`，移位暫存器便退化成單一級。關鍵字選哪一個，直接決定了合成出的硬體。

第 4 章的對應規則正好補上另一半：

- **循序（帶時脈）邏輯 → 非阻塞式 `<=`。**
- **組合邏輯 → 阻塞式 `=`。**

守住這條規則，就能避開絕大多數與指定相關的錯誤。

## 重置

正反器通常需要重置以達到已知狀態。有兩種風格。

### 同步重置

重置在時脈緣取樣，與其他輸入相同：

```verilog
always @(posedge clk) begin
    if (rst)
        q <= 1'b0;
    else
        q <= d;
end
```

同步重置讓所有邏輯都留在帶時脈的域內，對時序分析和多數 FPGA 架構都很友善，缺點是必須有運作中的時脈才能生效。

### 非同步重置

重置不受時脈影響、立即生效，做法是讓它出現在敏感度列表裡：

```verilog
always @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        q <= 1'b0;
    else
        q <= d;
end
```

非同步重置（此處為低電位有效的 `rst_n`）在重置訊號拉低的瞬間就強制進入該狀態，即使沒有時脈也成立。它的缺點出在重置的*釋放*：若重置在太靠近時脈緣的時刻取消，正反器可能進入亞穩態（metastable），所以釋放訊號必須先同步化。

在一個時脈域（clock domain）內選定一種風格，並一致地套用。同一個域內混用重置風格會帶來麻煩。

> **設計意圖。** 重置是一個承諾：「重置之後，每個狀態元素持有已知的值。」
> 為每個正反器寫好重置分支、並保持風格一致，就是把這個承諾說清楚。
> 「重置後 `q == 0`」這類斷言（第三部）能把承諾變成工具可以查核的條件。

## 阻塞式/非阻塞式指定的競態

若在同一個時間步內，一個區塊以 `=` 指定某變數，另一個區塊又去讀它，結果便取決於 simulator 執行各區塊的先後順序，這就是競態。守住上述兩條規則（帶時脈用 `<=`、組合邏輯用 `=`，且同一訊號絕不混用），就能消除這類競態。不要用兩個 `always` 區塊指定同一個變數，也不要對同一個變數混用 `=` 與 `<=`。

## 完整的暫存器範例

```verilog
module counter #(
    parameter WIDTH = 8
) (
    input  wire             clk,
    input  wire             rst_n,
    input  wire             en,
    output reg  [WIDTH-1:0] count
);
    always @(posedge clk or negedge rst_n) begin
        if (!rst_n)
            count <= {WIDTH{1'b0}};
        else if (en)
            count <= count + 1'b1;
    end
endmodule
```

留意這個結構：非同步重置在前，接著才是同步行為。`count` 在 `en` 為低時維持原值，這是帶時脈區塊裡刻意的狀態保持，而非閂鎖器。

## 常見陷阱

- **在帶時脈邏輯中使用阻塞式指定。** 這會破壞移位暫存器並引發競態，請改用 `<=`。
- **對同一個變數混用 `=` 與 `<=`。** 依規則每個區塊只選一種。
- **兩個區塊驅動同一個暫存器。** 每個狀態元素只能有一個驅動者。
- **在同一個時脈域內混用重置風格。** 選定同步或非同步，然後堅持到底。
- **忘了替需要已知初始值的狀態加上重置。** 未重置的正反器以 `x` 啟動。

## 小結

- 帶時脈的 `always @(posedge clk)` 區塊會推斷出正反器。
- 帶時脈邏輯用 `<=`，組合邏輯用 `=`。
- 同步重置留在時脈域內；非同步重置立即生效，但釋放訊號需要同步化。
- 每個暫存器只留一個驅動者，並在同一個域內維持一致的重置風格。
