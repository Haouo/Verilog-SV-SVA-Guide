# 第一部 · 7. 面向合成的撰寫

[← 有限狀態機](06-finite-state-machines.md) · [目錄](../README.md) · [下一章：測試平台基礎 →](08-testbench-essentials.md)

## 學習目標

- 撰寫模擬與合成結果一致的 RTL。
- 識別並避免導致不一致的語言結構。
- 套用一份簡短的合成安全習慣清單。

## 黃金法則：模擬必須與合成一致

合成工具從你的 RTL 建構出閘級電路；模擬器將你的 RTL 作為程式執行。兩者應該一致，但 Verilog 的某些特性可能使它們產生分歧。大多數存活到矽晶片上的 RTL 錯誤都來自這類不一致。本章彙整能讓兩者保持同步的習慣。其中幾個已在前幾章介紹過；此處將它們整合成一份清單。

## 避免閂鎖器

第 4 章已詳述，此處重申，因為它是最常見的合成意外。組合 `always` 區塊若未在每條路徑上對每個輸出賦值，就會推斷出閂鎖器（latch）。在區塊頂端設定預設值，或以完整的 `if`/`else` 與 `case`/`default` 撰寫，可防止此問題。

```verilog
always @* begin
    y = 1'b0;          // default assignment
    if (sel) y = a;    // override; no latch
end
```

## 完整且正確的敏感度

組合邏輯請使用 `always @*`，使敏感度列表（sensitivity list）天然完整（第 4 章）。手動撰寫的列表若遺漏某個訊號，模擬器就會錯過合成後硬體必然執行的更新。

## 阻塞式與非阻塞式指定

帶時脈的區塊使用 `<=`；組合區塊使用 `=`（第 5 章）。這條單一規則能防止最常見的模擬/合成競態。對同一訊號絕不混用兩者，且每個暫存器只有一個驅動者。

## 對需要重置的狀態元素執行重置

未重置的正反器在模擬中以 `x` 啟動，在硬體中則是未定義值。請決定哪些狀態需要確定的重置值並加以重置。在同一個時脈域內保持一種重置風格（第 5 章）。

## 避免在 RTL 中使用不可合成的語言結構

某些語言結構只屬於測試平台（testbench）。請將它們排除在可合成模組之外：

- `initial` 區塊（除非你的工具支援 FPGA RAM/ROM 初始化的特殊用法）。
- 延遲（delay），如 `#10`。
- `$display`、`$finish` 等系統任務（system task）。
- `===` 與 `!==`（它們涉及 `x`/`z`，而真實硬體不存在此狀態）。
- `real` 與 `time` 型別。
- 無界的 `while`/`forever` 迴圈。請使用有常數邊界的 `for` 迴圈，工具會將其展開。

## 不要依賴 `x` 樂觀假設或 pragma

兩個特別的陷阱：

- **`full_case` / `parallel_case`**（第 4 章）告訴合成工具假設某些模擬器不假設的事。應避免；改為撰寫完整的 `case` 語句。
- **`casex`** 在比對時將 `x` 視為 don't-care，可能在模擬中隱藏真實的 `x`，同時合成出不同的邏輯。優先使用 `casez`，或帶有 `default` 的普通 `case`。

## 保持算術位元寬度明確

寬度推斷（第 3 章）是靜默的。一個因運算式寬度來自較窄運算元而溢位的中間結果，在模擬與合成時會*以同樣錯誤的方式*運作——這是邏輯錯誤，而非不一致，但同樣有害。請明確指定中間訊號的寬度，使預期範圍清楚可見。

## 合成安全清單

在認為一個 RTL 區塊完成之前：

- [ ] 組合區塊使用 `always @*`，且在每條路徑上對每個輸出賦值。
- [ ] 帶時脈區塊使用 `<=`；組合區塊使用 `=`。
- [ ] 每個暫存器只有一個驅動者，且在需要時有確定的重置值。
- [ ] 每個時脈域只有一種重置風格。
- [ ] 每個 `case` 都有 `default`；不使用 `full_case`/`parallel_case`；不使用 `casex`。
- [ ] 可合成程式碼中沒有 `initial`、延遲或系統任務。
- [ ] 在可能溢位之處，算術位元寬度明確指定。

> **設計意圖。** 面向合成的撰寫，就是「我所模擬的就是我所建構的」這個意圖。
> 清單上的每個習慣，都消除了兩個視角產生分歧的一種可能。
> 斷言（第三部）是互補的工具：它們陳述結構本身無法表達的意圖，
> 並在模擬一偏離就立即觸發——包括本章致力防止的各種不一致。

## 常見陷阱

- 依賴模擬器對 `x` 的處理方式來確認設計正確。
- 在本應合成的模組中遺留零散的 `initial` 或延遲。
- 假設工具會對不完整的 `case`「照你的意思做」——工具遵循語言規範，而非你的意圖。

## 小結

- 目標是模擬與合成共享同一種行為。
- 避免閂鎖器、使用完整的敏感度、遵循 `<=`/`=` 規則，並對需要的狀態執行重置。
- 將僅屬測試平台的語言結構排除在 RTL 之外。
- 避免 `case` pragma 與 `casex`；保持位元寬度明確。
