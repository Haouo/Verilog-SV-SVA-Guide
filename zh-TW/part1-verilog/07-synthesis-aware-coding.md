# 第一部 · 7. 面向合成的撰寫

[← 有限狀態機](06-finite-state-machines.md) · [目錄](../README.md) · [下一章：測試平台基礎 →](08-testbench-essentials.md)

## 學習目標

- 撰寫 simulation 與合成結果一致的 RTL。
- 識別並避免導致不一致的語言結構。
- 套用一份簡短的合成安全習慣清單。

## 設計者的心智模型

面向合成的撰寫，講究的是讓 simulation、synthesis 與設計者的意圖描述出同一份硬體。simulator 能執行
許多無法變成閘的語法構件，synthesis 工具也可能合法地把設計者以為有意義的行為最佳化掉。最安全的 RTL，
會盡量不留任何讓這三者出現落差的空間。

本章每一條規則，都是在守護這份一致：完整的指定避免意外產生儲存元件，明確的位元寬度避免靜默截斷，
不依賴 `x` 樂觀假設則避免 simulation 把硬體的不確定性藏起來。重點不在追求風格純粹，而在於讓設計的
原意經過各種工具之後仍然一致。

## 黃金法則：simulation 必須與合成一致

合成工具把你的 RTL 建成閘級電路，simulator 則把同一份 RTL 當成程式來跑。兩者本該一致，但 Verilog 的某些特性會讓它們出現分歧。多數能一路存活到矽晶片上的 RTL 錯誤，都源自這類不一致。本章把能讓兩者保持同步的習慣彙整起來，其中幾個前幾章已經介紹過，這裡整合成一份清單。

## 避免閂鎖器

這在第 4 章已詳述，這裡再提一次，因為它是最常見的合成意外。組合 `always` 區塊若沒有在每條路徑上對每個輸出賦值，就會推斷出閂鎖器（latch）。在區塊頂端設好預設值，或寫成完整的 `if`/`else` 與 `case`/`default`，就能避免。

```verilog
always @* begin
    y = 1'b0;          // default assignment
    if (sel) y = a;    // override; no latch
end
```

## 完整且正確的敏感度

組合邏輯請用 `always @*`，讓敏感度列表（sensitivity list）天生就完整（第 4 章）。手寫的列表一旦漏掉某個訊號，simulator 就會錯過合成後硬體照樣會做的更新。

## 阻塞式與非阻塞式指定

帶時脈的區塊用 `<=`，組合區塊用 `=`（第 5 章）。光是這一條規則，就能防住最常見的那一類 simulation / synthesis 競態。同一訊號絕不混用兩者，每個暫存器也只留一個驅動者。

## 對需要重置的狀態元素執行重置

未重置的正反器在 simulation 中以 `x` 啟動，在硬體中則是未定義值。請判斷哪些狀態需要確定的重置值，並替它們加上重置。同一個時脈域內維持單一種重置風格（第 5 章）。

## 避免在 RTL 中使用不可合成的語言結構

有些語法構件只該出現在測試平台（testbench）裡。請把它們擋在可合成模組之外：

- `initial` 區塊（除非你的工具支援 FPGA RAM/ROM 初始化的特殊用法）。
- 延遲（delay），如 `#10`。
- `$display`、`$finish` 等系統任務（system task）。
- `===` 與 `!==`（它們會去比對 `x`/`z`，而真實硬體沒有這種狀態）。
- `real` 與 `time` 型別。
- 無界的 `while`/`forever` 迴圈。請改用有常數邊界的 `for` 迴圈，工具會把它展開。

## 不要依賴 `x` 樂觀假設或 pragma

兩個特別的陷阱：

- **`full_case` / `parallel_case`**（第 4 章）會叫合成工具去假設某些 simulator 並不假設的事。請避開它們，改寫完整的 `case` 語句。
- **`casex`** 在比對時把 `x` 當成 don't-care，可能在 simulation 中藏住真正的 `x`，同時又合成出不一樣的邏輯。請優先用 `casez`，或帶有 `default` 的普通 `case`。

## 保持算術位元寬度明確

寬度推斷（第 3 章）是無聲無息的。某個中間結果若因運算式寬度取自較窄的運算元而溢位，在 simulation 與合成時都會*以同樣錯誤的方式*運作：這是邏輯錯誤，不是不一致，但一樣有害。請替中間訊號明確標好寬度，讓預期範圍一目了然。

## 合成安全清單

在認定一個 RTL 區塊已經完成之前：

- [ ] 組合區塊使用 `always @*`，且在每條路徑上對每個輸出賦值。
- [ ] 帶時脈區塊使用 `<=`；組合區塊使用 `=`。
- [ ] 每個暫存器只有一個驅動者，且在需要時有確定的重置值。
- [ ] 每個時脈域只有一種重置風格。
- [ ] 每個 `case` 都有 `default`；不使用 `full_case`/`parallel_case`；不使用 `casex`。
- [ ] 可合成程式碼中沒有 `initial`、延遲或系統任務。
- [ ] 在可能溢位之處，算術位元寬度明確指定。

> **設計意圖。** 面向合成的撰寫，就是要說清楚「我在 simulation 看到的，正是我建構出來的」。
> 清單上的每個習慣，都堵住了兩種視角產生分歧的一條途徑。
> 斷言（第三部）則是互補的工具：它陳述結構本身說不清的意圖，
> 並在 simulation 一偏離就立刻觸發，包括本章極力要防的各種不一致。

## 常見陷阱

- 拿 simulator 處理 `x` 的方式來認定設計沒問題。
- 在本該合成的模組裡留下零星的 `initial` 或延遲。
- 以為工具會對不完整的 `case`「照你的意思辦」：工具只遵循語言規範，不管你心裡怎麼想。

## 小結

- 目標是讓 simulation 與合成共用同一種行為。
- 避免閂鎖器、用完整的敏感度、守住 `<=`/`=` 規則，並替需要的狀態加上重置。
- 把只屬於測試平台的語法構件擋在 RTL 之外。
- 避開 `case` pragma 與 `casex`，並把位元寬度寫明確。
